# 應用程式骨架與聊天體驗改善 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 前端改寫為 React + TypeScript 的兩欄式應用骨架（可收合的功能選單與對話列表），聊天串流改用 NDJSON 以即時顯示思考過程，並支援「重新送出」重新產生回答。

**Architecture:** 後端 `OllamaClient` 改為產出 `ChatDelta`（thinking / content），兩個串流端點（送訊息、regenerate）共用一個 NDJSON 串流函式；FastAPI 改為提供 `frontend/dist`。前端是 Vite 建置的 SPA：HashRouter、功能註冊表產生選單、`useChat` hook 管理串流狀態。

**Tech Stack:** 後端 Python 3.12 / FastAPI / httpx / SQLite / pytest（不變）；前端 Node 22 LTS、React、TypeScript、Vite、react-router、lucide-react、CSS Modules、Vitest + Testing Library（jsdom）、ESLint

**Spec:** `docs/superpowers/specs/2026-10-16-app-shell-design.md`（前一版：`docs/superpowers/specs/2026-10-16-ollama-chat-design.md`）

## Global Constraints

- `.gitignore` 必須包含 `node_modules/`
- localStorage 鍵名：`phoebe.nav.collapsed`、`phoebe.chat.listCollapsed`；讀寫包在 try/catch，失敗時預設展開
- 視窗寬度 < 1024px 時對話列表預設收合，可手動展開（不寫入偏好）
- 介面與視窗四邊間距 16–24px，圓角卡片加陰影；訊息區最大寬度 800px 置中
- 串流事件：`{"type":"thinking","text"}`、`{"type":"content","text"}`、`{"type":"done","message_id"}`、`{"type":"error","detail"}`；`application/x-ndjson`，`ensure_ascii=False`，每行 `\n` 結尾
- 串流開始前失敗 → HTTP 503：`OllamaUnavailable` 的 detail 為「無法連線到 Ollama」，其他 `OllamaError` / `httpx.HTTPError` 用 `str(e)`
- 串流中途失敗 → 不存 assistant，送 `error` 事件（detail 為 `str(e)`，空字串時「回覆中斷」）後正常結束
- 存進 DB 與送給模型的歷史只有 content，不含 thinking
- regenerate：非本人對話 404；最後一則不是 `user`（含沒有訊息）→ 409 `{"detail": "沒有需要重新產生的回答"}`
- 新設定：`CHAT_THINK`（預設 `true`）、`FRONTEND_DIST`（預設 `<專案根>/frontend/dist`）

## Review Focus

1. **網址指向不存在或別人的對話**（`#/chat/999`）：期望顯示「找不到這個對話」並導回 `#/chat`，而不是空白或卡住。→ Task 5 `ChatPage redirects to #/chat when conversation is 404`
2. **localStorage 無法使用**（無痕模式、被封鎖時存取會丟例外）：期望介面照常顯示、預設展開，不會整頁壞掉。→ Task 4 `usePersistentState falls back to default when localStorage throws`
3. **模型只思考、沒有產生回答**（只有 thinking 就 done）：期望後端存一則空的 assistant 並送 done；前端結束串流，思考區塊收合，不會一直顯示「思考中…」。→ Task 2 `test_thinking_only_reply_saves_empty_assistant`、Task 5 `useChat finishes when done arrives without content`
4. **輸入只有空白就按 Enter**：期望什麼都不做（不送出、不清空、不出現空泡泡）。→ Task 5 `Composer ignores whitespace-only input`
5. **連點「重新送出」**：期望串流開始後按鈕就消失，只會發出一次 regenerate。→ Task 5 `retry button disappears while streaming`

  - `ChatItem`：`{ key: string; role: "user" | "assistant"; content: string; thinking: string; thinkingStartedAt?: number; thinkingSeconds?: number; status: "done" | "streaming" | "error"; error?: string; interrupted?: boolean }`
  - `useChat(options: { conversationId: number | null; onConversationCreated(id: number): void; onFinished(): void }): { items: ChatItem[]; streaming: boolean; canRetry: boolean; loadError: string | null; send(text: string): Promise<void>; retry(): Promise<void> }`
    - 換 `conversationId` 時載入對話（回應晚到時，若 id 已變就丟棄）；404 → `loadError = "找不到這個對話"`
    - `send`：`conversationId` 為 null 時先 `api.createConversation()` 並呼叫 `onConversationCreated`；立即加入 user 與 streaming 的 assistant 項目
    - 事件處理：thinking → 記錄 `thinkingStartedAt`（第一次）、附加 thinking；第一個 content → `thinkingSeconds = Math.round((now - start)/1000)`（有 thinking 時），附加 content；done → status done、呼叫 `onFinished`；error 事件 → status error、`interrupted = content !== ""`、`error = detail`；串流結束沒有 done → 同 error，detail「回覆中斷」；`ApiError` → status error、`error = e.message`；其他例外 → `error = "無法連線到伺服器"`
    - `canRetry`：`!streaming` 且（最後一項是 user，或最後一項是 status error 的 assistant）
    - `retry`：移除最後一個 error 的 assistant 項目（如果有），加入新的 streaming assistant，呼叫 `api.regenerate`；409 → 重新載入對話
    - 串流期間呼叫 `setBlocked("回覆產生中，確定要離開？")`，結束時 `setBlocked(null)`
  - `ChatPage`：讀 `:id` 參數；`loadError` 時顯示訊息並導向 `#/chat`；對話列表收合用 `usePersistentState("phoebe.chat.listCollapsed", false)`，`useMediaQuery("(max-width: 1023px)")` 為 true 時強制收合
  - `Composer({ disabled, onSend(text: string): void })`：Enter（非 `isComposing`、非 Shift）且 `text.trim() !== ""` 時呼叫 `onSend(text)` 並**立刻**清空
  - `ThinkingBlock({ thinking, startedAt, seconds, live })`：`live` 時展開，標題「思考中…」加上每秒更新的秒數；不 live 時預設收合、標題「已思考 {seconds} 秒」，點擊切換
  - `MessageBubble`：status error 時顯示 `error`；`interrupted` 時在內容後加「（回覆中斷）」；`white-space: pre-wrap`
  - 重新送出按鈕：`canRetry` 時顯示在最後一則訊息下方，文字「重新送出」
